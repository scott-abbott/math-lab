# Simple STL -> G-code Slicer

A small, from-scratch Python slicer. Loads an STL, slices it into layers,
generates perimeters and infill, and writes standard G-code. All lengths
are in **mm**, all temperatures in **degrees C**.

Dependencies: `numpy`, `shapely` (polygon offsetting), `matplotlib`
(notebook previews only).

## `slicer.ipynb` — the notebook

`slicer.ipynb` is the main, self-contained version: the whole pipeline in
order, one section per stage, with plots for verification. It imports
nothing from `slicer/` — everything it needs is defined in its own cells,
so you can edit any stage in place and re-run.

```python
cfg = PrintConfig(layer_height=0.2, num_perimeters=3, infill_density=0.3)
layers = slice_model(load_stl("part.stl"), cfg, pattern=my_pattern)
plot_layer(layers[10])                      # look before you print
open("part.gcode", "w").write(layers_to_gcode(layers, cfg))
```

Slicing and G-code emission are separate there: `slice_model()` returns
`SlicedLayer` objects holding the raw toolpaths (easy to plot and
measure), and `layers_to_gcode()` turns those into G-code as a second
step.

## `main.py` — the CLI

The same slicer as an importable package plus a command-line front end.

```bash
python main.py part.stl part.gcode
```

Common options (see `python main.py --help` for the full list):

```bash
python main.py part.stl part.gcode \
    --layer-height 0.2 \
    --extrusion-width 0.45 \
    --perimeters 3 \
    --infill-density 0.25 \
    --nozzle-diameter 0.4 \
    --filament-diameter 1.75 \
    --nozzle-temp 205 \
    --bed-temp 60
```

## Custom infill patterns

Infill is generated by sweeping a family of parallel lines across the
part and, for each line, offsetting it with a function `f(x) -> y`. The
default `f(x) = 0` gives plain straight-line infill. Built-ins:

```bash
python main.py part.stl part.gcode --infill-pattern lines   # default
python main.py part.stl part.gcode --infill-pattern sine
python main.py part.stl part.gcode --infill-pattern zigzag
python main.py part.stl part.gcode --infill-pattern square
```

To use your own pattern, write a `.py` file with a function of that
signature and point the CLI at it:

```python
# my_pattern.py
import math

def my_wave(x: float) -> float:
    return 0.8 * math.sin(x / 2.0) + 0.1 * math.sin(x / 11.0)
```

```bash
python main.py part.stl part.gcode \
    --infill-pattern-file my_pattern.py --infill-pattern-func my_wave
```

Infill line spacing is derived from `extrusion_width / infill_density`;
the pattern function only controls the shape each line traces as it
sweeps across x, in a frame rotated to `--infill-angle` (alternating
+90 degrees every other layer by default, `--no-alternate-infill-angle`
to disable).

## What it does / doesn't do

- Parses binary and ASCII STL directly (no external mesh library).
- Slices via triangle/plane intersection, chains segments into loops,
  and resolves holes/nesting automatically (even-odd rule), so
  multi-body and holed parts work.
- Generates N perimeter shells (offset inward by `extrusion_width`)
  and infill inside the innermost shell.
- Computes extrusion (`E`) from a rectangular bead cross-section
  (`extrusion_width x layer_height`) and the filament's circular
  cross-section.
- Uses absolute X/Y/Z positioning (`G90`) and relative extrusion
  (`M83`), with a simple retract/unretract on every travel move.
- Does **not** generate support material, bridging, or overhang
  handling — flagged out of scope for this version.
- Assumes a single, reasonably clean/watertight input mesh; it does
  not attempt to repair non-manifold geometry.

## Project layout

```
slicer.ipynb       self-contained notebook version (recommended)
slicer/
  config.py       PrintConfig dataclass (all settings)
  stl_reader.py    binary/ASCII STL parser
  mesh_slicer.py   triangle/plane intersection + loop chaining
  geometry.py      perimeter offsetting, infill region (shapely)
  infill.py        infill line generation from a pattern function f(x)
  patterns.py      built-in example patterns (lines/sine/zigzag/square)
  gcode.py         G-code writer (extrusion math, retraction, headers)
  engine.py        orchestrates STL -> G-code
main.py            CLI
examples/
  make_test_stl.py generates cube.stl / hollow_box.stl test parts
  plot_layer.py    renders a PNG preview of one G-code layer's toolpath
```
